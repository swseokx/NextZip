# NextZip 위협 모델

작성: 2026-11-22 (M5 보안·안정화). 대상: `main` + `m5-hardening` 브랜치의 Windows 빌드.
점검 결과와 남은 일은 [self-review.md](self-review.md)에 있습니다.

## 1. 지켜야 할 것

| 자산 | 왜 중요한가 |
|---|---|
| 사용자 파일 (출력 폴더 밖) | 악성 압축 파일이 덮어쓰거나 지우면 피해가 바로 생김 |
| 사용자 계정의 실행 권한 | 디코더 버그로 코드가 실행되면 사용자 권한을 그대로 얻음 |
| 디스크·메모리 | 압축 폭탄으로 디스크를 채우거나 PC를 멈추게 할 수 있음 |
| 압축 암호 | 메모리·로그·임시 파일에 남으면 유출 |
| Windows 보호 장치 (SmartScreen, MotW, Defender) | 압축을 거치면서 표시가 사라지면 사용자가 경고를 못 받음 |

## 2. 공격자와 진입점

- **주 공격자: 압축 파일을 만든 사람.** 사용자가 메일·메신저·웹에서 받은 파일을 더블클릭하거나 탐색기 메뉴로 풉니다.
  공격자는 파일의 모든 바이트를 고를 수 있지만 PC에는 아무 권한이 없습니다.
- 진입점: `nextzip.exe`(GUI), 셸 확장 `nextzip_shell.dll`(탐색기 안에서 목록·제목 읽기), `nz.exe`(CLI).
  셋 다 결국 `nz-archive`의 `list`/`extract`를 부릅니다.
- 범위 밖: 이미 사용자 권한을 가진 로컬 공격자, 관리자, 물리 접근, 업데이트 서버(업데이트 기능이 아직 없음).

## 3. 신뢰 경계와 데이터 흐름

```
압축 파일 (신뢰 안 함)
   │
   ├─▶ nextzip.exe / nz.exe  ── 중간 무결성, 사용자 권한
   │     ├─ nz-archive: 형식 판별, ZIP 중앙 디렉터리·ALZ·EGG 파서(Rust), 이름 정리(safepath)
   │     ├─ nz-core: ZIP Deflate·7z·tar 계열 해제 (Rust + C 코덱 libdeflate·zstd·liblzma·bzip2·lz4)
   │     └─ 파일 쓰기는 항상 이 프로세스가 함
   │
   ├─▶ nz-decode.exe (격리 디코더) ── 낮은 무결성, 권한 제거, 잡 오브젝트(3 GiB, 자식 프로세스 금지),
   │     │                             동적 코드·확장 지점·원격 이미지 금지
   │     └─ RAR(UnRAR C++), nz-formats(레거시·희귀 형식, unarc-rs 등), ZIP 고급 방식, 7z 고급 코더
   │        → 파일을 쓰지 않고 파이프로 데이터만 돌려줌 (L/S/D/F/E/K 프레임)
   │
   └─▶ nz-decode.exe --scan (AMSI 검사기) ── 중간 무결성, 데이터를 받아 AmsiScanBuffer 결과만 돌려줌
```

경계 1(압축 파일 → 프로세스)은 모든 바이트가 공격자 입력입니다. 경계 2(격리 디코더 → 부모)도
신뢰하지 않습니다. 부모는 디코더가 보낸 항목 번호·크기를 검증하고(요청하지 않은 항목, 중복, 한도 초과는 실패),
이름은 목록 단계에서 부모가 직접 정리합니다.

## 4. 위협과 대응 (스펙 9장 기준)

| # | 위협 | 대응 | 상태 |
|---|---|---|---|
| T1 | 경로 조작 (Zip Slip, `..`, 절대 경로, 드라이브 문자, `\\?\`, UNC) | `safepath::sanitize`(nz-archive)·`walk::safe_relative`(nz-core). 절대 경로·`..`가 하나라도 있으면 압축 파일 전체 거부(사용자 결정) | 구현, M5에서 보강 |
| T2 | Windows 이름 규칙 악용 (`.. `·`...` 끝 공백·점, `:` ADS, NUL, CON/NUL 등 예약어) | 끝의 점·공백 제거 뒤 `..` 판정, `:`·NUL 거부, 예약어는 앞에 `_` | M5에서 nz-core 쪽 보강 |
| T3 | 링크로 대상 밖 쓰기 | 격리 경로는 링크를 만들지 않음. tar 계열은 대상 안을 가리키는 링크만 만들고, 이미 만든 링크를 거쳐 가는 경로는 거부 | M5에서 탈출 버그 수정 |
| T4 | 압축 폭탄 | 선언 크기 합계 ≤ 압축 파일 × 4096 + 1 GiB(최대 64 GiB), ZIP 겹치는 데이터·파일 밖 데이터 거부, 격리 경로는 실제 출력량으로 같은 한도, 디코더 시간·메모리 감시 | 대부분 구현, 일부 공백(자체 점검 참조) |
| T5 | 디코더 메모리 오류로 코드 실행 | Rust 파서, C/C++ 레거시 디코더는 nz-decode 샌드박스, cargo-fuzz 11개 타깃 | 일부 C 코덱은 주 프로세스 안(자체 점검 참조) |
| T6 | 디코더 폭주(무한 루프·무한 출력)로 PC 멈춤 | 부모: 300초 무응답 시 종료, 잡 3 GiB. 자식: 시간(30초 + MiB당 1초)·커밋 메모리 감시 후 스스로 종료. unarc-rs HA 디코더는 기록된 크기를 넘으면 실패하도록 패치 | M5 |
| T7 | 악성 실행 파일을 풀어 사용자가 실행 | AMSI 검사(기본 켜짐, 끌 수 있음), 감지 항목은 쓰지 않고 경고 창 | M5 |
| T8 | MotW 누락 | 압축 파일의 Zone.Identifier가 인터넷(3) 이상이면 푼 파일 모두에 전파 | M5 |
| T9 | 암호 유출 | 암호는 파이프(stdin)로만 자식에 전달, 명령줄·로그에 남기지 않음. 사용 후 제로화는 아직 없음 | 일부 |
| T10 | 약한 암호화 | ZipCrypto는 해제만 지원(생성 기능 없음) | 구현 |
| T11 | 업데이트 변조 | 업데이트 기능 없음. 설치 파일 서명은 자체 서명 테스트 인증서 | 범위 밖(1.0 전) |

## 5. 남은 위험 요약

자체 점검에서 고치지 않고 남긴 항목(사용자 결정 필요)은 [self-review.md](self-review.md) 5절에 모았습니다.
외부 보안 검토는 아직 받지 않았습니다. 이 문서와 자체 점검표가 검토 요청 자료입니다.
