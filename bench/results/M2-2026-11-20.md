## 3. 콜드 스타트 (K8)

`nextzip.exe --probe-startup <file>`: 프로세스 생성 시각(GetProcessTimes)부터 첫 WM_PAINT 완료까지. release 빌드, 각 10회, 다른 빌드·테스트가 없는 상태.

| 시나리오 | 중앙값 | 최소 | 최대 | 10회 |
|---|---|---|---|---|
| 빈 상태 (`nextzip.exe`) | **174 ms** | 160 | 208 | 168.9 186.0 160.1 207.9 164.8 169.6 172.1 175.6 205.6 180.4 |
| 압축 파일 열기 (`nextzip.exe project-assets.7z`, 77개 파일) | **202 ms** | 193 | 208 | 201.7 207.6 199.3 206.7 192.9 208.3 204.3 201.6 199.1 198.8 |

단계별(디버그 추적, 대략): 프로세스 시작 → main 11 ms, COM·comctl 초기화 ~13 ms, **Direct2D/DirectWrite 팩토리·글꼴 ~50 ms**, 도구 모음·목록 생성 ~45 ms, 첫 그리기 ~170 ms. 줄인 것: 시스템 글꼴 컬렉션 조회를 파일 존재 확인으로 교체, 셸 이미지 목록을 첫 그리기 이후로 미룸(165–254 → 160–208 ms). 압축 파일 열기는 기준을 중앙값으로 약 2 ms 넘습니다. 남은 후보: D2D 팩토리 생성을 첫 그리기와 병렬로, 트리 생성 지연.

## 5. Windows 11 셸 메뉴

- `crates/nz-shell` → `nextzip_shell.dll`: `IExplorerCommand` 루트 "NextZip"과 하위 명령 **여기에 풀기 / 폴더로 풀기 / 압축…**. 압축 파일이 아닌 선택에서는 풀기 명령을 숨깁니다. 실행은 DLL 옆의 `nextzip.exe --extract-here|--extract-folder|--compress`.
- 검증: `tests/dll.rs`가 레지스트리 없이 탐색기처럼 DLL을 로드(DllGetClassObject → IClassFactory → IExplorerCommand)해 제목과 zip/txt 선택별 상태를 확인. 통과.
- 등록 방법 2가지를 `crates/nz-shell/packaging/`에 준비했고, **둘 다 실행하지 않았습니다** (실행 전 사용자 확인 필요):
  - `register-hkcu.ps1`: HKCU\Software\Classes만 기록(CLSID, `*\shell\NextZip`, `Directory\shell\NextZip`). Windows 11에서는 "추가 옵션 표시" 아래에 나타남. `-WhatIf`로 미리보기, `-Unregister`로 제거.
  - `register-sparse.ps1` + `AppxManifest.xml`: 서명된 sparse 패키지로 Windows 11 **최상위** 메뉴에 표시. 코드 서명 인증서(.pfx)와 그 신뢰 설치가 필요(보안 설정이므로 사용자가 직접).
- 두 방법 모두 **파일 연결(ProgID·기본 앱)은 바꾸지 않습니다.**
- **2026-11-21 사용자 확인 후 HKCU 방식으로 등록함**: release 빌드를 `%LOCALAPPDATA%\Programs\NextZip`에 복사하고 그 DLL 경로로 등록. 레지스트리 3개 키 확인, 레지스트리를 거친 COM 활성화(CoCreateInstance) 성공. 제거: `register-hkcu.ps1 -Unregister`.
- 미검증: 실제 탐색기에서의 표시·실행 (탐색기 재시작은 사용자가 직접 하기로 함). sparse 패키지(최상위 메뉴)는 미등록.

## 6. 퍼징

- `fuzz/` (cargo-fuzz 형식, 워크스페이스 밖): 타깃 `archive`(ZIP·7z·tar.zst·RAR 등 내용 판별), `archive_alz`, `archive_egg`, `bzip2`(표준·ALZ 변형), `names`(코드페이지 판별 + zip-slip 정리).
- 본문은 `nz_archive::fuzzing`에 있고, 각 입력에 대해 **패닉 없음 + 출력 폴더 밖 쓰기 없음 + 정리된 경로는 상대 경로의 일반 구성요소만**을 단언합니다.
- 이 PC에는 stable 툴체인만 있어 libFuzzer 실행은 못 했습니다(nightly·cargo-fuzz 설치는 외부 다운로드라 하지 않음). 대신 같은 본문을 결정적 변이(비트 반전, 경계값, 32비트 필드 덮어쓰기, 자르기, 복제, 삭제)로 돌리는 stable 테스트 `crates/nz-archive/tests/fuzz_smoke.rs`를 넣었습니다.
  - 시드: ALZ 4종, EGG 7종, 옛 ZIP 1종, RAR 4종, bzip2 3종, 이름 4종 (`NZ_FUZZ_CORPUS=<dir>`로 cargo-fuzz용 코퍼스로 내보내기 가능).
  - 기본 실행(시드당 120회)은 `cargo test`에 포함. 긴 실행(`NZ_FUZZ_ITERS=3000`, release): 아카이브 약 5만 건 + bzip2·이름 수십만 건, 362초, 통과.
  - **발견·수정 1건**: EGG/tar 헤더의 범위 밖 시각 값에서 `SystemTime` 덧셈 오버플로 패닉 → 검사된 덧셈으로 교체.
- 실행 방법: `cargo +nightly fuzz run archive fuzz/corpus/archive` (nightly + `cargo install cargo-fuzz` 필요).
